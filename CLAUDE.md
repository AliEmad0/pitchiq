# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Environment — read this first

The project lives on the WSL Ubuntu filesystem. When Claude Code is launched from Windows, the working directory is a UNC path (`\\wsl.localhost\ubuntu\...`). **Node-toolchain commands cannot run from a Windows shell with a UNC cwd** — any tool that spawns `cmd.exe` (npm, npx, pnpm dlx, package postinstall scripts) fails with "UNC paths are not supported."

**All `pnpm`/`node`/`npx` commands must be invoked through WSL**, sourcing `nvm` to pick up Node 22:

```bash
wsl -d Ubuntu -- bash -c 'source $HOME/.nvm/nvm.sh && nvm use 22 > /dev/null && cd /home/aliemad/projects/pitchiq && pnpm <command>'
```

The Bash/Edit/Read tools work fine on the UNC path because they don't spawn `cmd.exe`.

## What this repo is

PitchIQ is a Premier League encyclopedia web app covering the complete history, 1992-93 → 2025-26 (34 seasons): standings, fixtures + match detail, team profiles + squads, player profiles, managers, a season-vs-season player comparison tool, leaderboards, a trivia layer, and an interactive historic map — with a Time-Machine theme that re-skins the UI per era, English + Arabic (RTL) localization, and motion.

**This repo contains the app + the committed data it renders.** The data lives as JSON snapshots under `data/`, refreshed by an **external pipeline** that opens data-only PRs here. This repo has no data-fetching/scraper code — it only reads the committed snapshots.

## Architecture

### Data flow — server-side reads from committed JSON

Sports data comes from **committed JSON snapshots** under `data/` — `standings-<season>.json`, `teams-<season>.json`, `players-<season>.json`, `fixtures-<season>.json`, `leaderboards-<season>.json`, `lineups-<season>.json`, `events-<season>.json`, plus a single `_meta.json` (refresh provenance) and a cross-season `search-index.json` (powers the ⌘K global search). These are produced and refreshed by an external data pipeline.

- **Read path is `src/data/loaders.ts`** — server-only async loaders (`loadStandings`, `loadTeams`, `loadPlayers`, `loadFixtures`, `loadLeaderboard`, `loadMeta`, plus derived `loadPlayer` / `loadFixture` / `loadSquad` / `loadTeamStats` / `loadLineup` / `loadEvents` / `loadCaptains` / `loadManagers` …). Each reads a JSON file via `readFile`, parses, and validates against a Zod schema in `src/data/schemas.ts`. Returns `null` on ENOENT / parse error / schema violation; `[]` for derived filters that match zero rows.
- **Server-only enforcement**: every loader + every `src/features/*/api.ts` fetcher starts with `import "server-only";`. The fetchers are thin adapters — they call the loaders and reshape the flat committed shape into the wire shapes page components consume.
- **⭐ All 54 extended per-season stats are ALREADY on the player rows** as `metrics.extended` (`ExtendedMetricsSchema`, added by TASK-M65) — touches, passes, clearances, fouls won, offsides, headed/left-footed goals, duels, blocks, the lot. Present on **~95% of rows from 2008 onward**. ⛔ **Do NOT add a loader for `data/player-history-stats.json`.** That 15.28 MB side file duplicates the rows exactly — verified over **58,303 field comparisons with 0 disagreements** (TASK-M83) — so reading it would cost 15 MB to learn nothing, and reading it from a request-time path would rebuild the Fluid Active-CPU shape TASK-M71 had to fix. It survives only because it may be the pipeline's rebuild source; the app must ignore it.
- **Route Handlers under `src/app/api/`** proxy the same fetchers for client-side use cases: `/api/search`, `/api/standings`, `/api/leaderboards/[kind]`, `/api/fixtures`, `/api/players/[id]`, `/api/players/search`, `/api/trivia`, `/api/admin/revalidate` (manual cache bust), `/api/health` (uptime + `_meta.json` freshness), and the dynamic OG-image routes under `/api/og/*`.

### Season model

- **34 seasons committed AND advertised (1992-93 → 2025-26).** `src/utils/season.ts#currentDataSeason()` (`= LATEST_DATA_SEASON`, 2025) is the default for every fetcher; `EARLIEST_SEASON` is 1992. `parseSeason` clamps `?season=` to `[EARLIEST_SEASON, currentDataSeason()]`. `getAvailableSeasons()` reads `_meta.json.seasons` (filtered `<= currentDataSeason()`), so the `<SeasonSwitcher>` lists exactly the committed seasons.
- **Stable player ids** — a player has ONE id across all seasons (a committed registry maps identity → id; the same id appears in multiple `players-<season>.json` files, one row per season played). `loadPlayer(id, season)` finds the per-season row. Never renumber ids — bookmarked `/players/<id>` URLs depend on them.
- **Entity-scoped season control** — on entity detail routes the global header `<SeasonSwitcher>` hides (`<HeaderSeasonSwitcher>` returns `null` when the path matches `/^\/(players|teams|managers)\/[^/]+$/`); `teams/[id]` + `managers/[id]` render a page-local `<EntitySeasonSwitcher>` scoped to the entity's own seasons (still `?season=`-driven, so still dynamically rendered).
- **`players/[id]` is the exception — it renders the current season server-side (SSG) and swaps history client-side.** It does NOT read `?season=` (reading `searchParams` de-statics every view — the Vercel Active-CPU regression, fixed 2026-07). Instead `<PlayerSeasonView>` holds the season subtree, and picking a season fetches `GET /api/players/[id]/profile?season=&locale=` (+ `/seasons`, `/api/trivia`) and swaps in place, syncing `?season=` via `window.location` + `history.pushState` (NOT `useSearchParams` — that would bail static prerender). Only the current season is server-rendered/indexed (matches the sitemap). `fixtures/[id]` is SSG via `generateStaticParams` + `dynamicParams`; all four detail pages set **`revalidate = false`** (see Cache strategy — a timer regenerated byte-identical pages at ~5s of CPU each).

### Cache strategy

The loaders read local JSON via `readFile` (no outbound fetches), so the Next fetch cache is not load-bearing for sports data.

**⛔ NO ROUTE MAY SET A POSITIVE `revalidate` — measured 2026-08-22, guarded by `tests/unit/route-revalidate.test.ts`.** Every page renders from committed JSON, and that JSON can only change through a data-refresh PR from the pipeline — a push to `main`, i.e. a production deploy, which rebuilds every page anyway. So a 24-hour window bought **nothing**: it paid to regenerate pages that came out byte-identical. And it was not cheap — Vercel's Observability → Functions view put `/en/game/legacy/47` at **4.97 seconds of Active CPU for a single invocation** (a Legacy page rebuilds its club's whole history out of all 34 season files), `/api/game/rivals/40` at 4.91s, and every Legacy club between 3.6s and 5.0s; across 51 clubs × 2 locales that was a recurring daily bill on the plan whose CPU cap already paused this project once (TASK-M71). Every force-static route now declares `revalidate = false` — cache until the next deploy, which is exactly when the data can differ. ⚠️ `revalidate = 0` is a **different thing** and stays allowed (it means "never cache", which is what `/api/trivia` deliberately is); what is forbidden is a positive number. ⚠️ The guard found **three routes on `revalidate = 60`** that a grep for `86400` missed. Cache-tag helpers live in `src/utils/cache-tags.ts` (convention enforced by `tests/unit/cache-tags.test.ts`); bust on demand via `GET /api/admin/revalidate?tag=<tag>&secret=<REVALIDATE_SECRET>`.

### Styling & i18n

- **Tailwind CSS v4** — config is CSS-based (`@theme inline { … }` blocks in `src/app/globals.css`). There is **no `tailwind.config.ts`**. `@custom-variant dark (&:where(.dark, .dark *))` binds `dark:` to the next-themes `.dark` class (not the OS).
- **Shadcn UI** installed on-demand (`pnpm dlx shadcn@latest add <component>`); aliases in `components.json`.
- **next-intl** — English (un-prefixed URLs) + Arabic (`/ar/*`, full RTL). The whole route tree is under `src/app/[locale]/`; `setRequestLocale` preserves SSG. Use CSS logical properties so RTL mirrors for free. See `docs/i18n-glossary.md`.
- **⛔ A paramless boundary file must NEVER call a next-intl SERVER API (TASK-M89).** `not-found.tsx` / `error.tsx` / `loading.tsx` / `template.tsx` receive **no `params`**, so they can never call `setRequestLocale()` — and calling `getTranslations()`/`getMessages()` without a locale resolves the request config to `defaultLocale` **and memoizes it for the entire render**. Next prerenders the boundary as part of its segment's shell, so the poisoning lands **before** the page and the shared layout render: three route-scoped `not-found.tsx` files silently shipped the **English catalog** on every `/ar/managers/[id]`, `/ar/teams/[id]` and `/ar/players/[id]` page (541 of 940 Arabic renders in a build). **Make them `"use client"` + `useTranslations`** — the client provider gets an explicit `locale` from the layout, so it cannot poison anything. Guarded by `tests/unit/i18n-boundary-locale.test.ts` (no exemptions, deliberately). Same family as the TASK-M72 `loading.tsx` soft-404s: a paramless boundary doing work its whole segment depends on.
- **⛔ Know whether a surface is PRERENDER or REQUEST-TIME before adding a data read (TASK-M82/M92).** `/players/[id]` is `force-static`, so it may read the big detail maps at prerender; `/api/trivia` is `export const revalidate = 0`, so **every** rule runs on **every request** and must not. The heavy files are `player-honours.json` (5 MB), `player-transfer-history.json` (8 MB) and `market-value-history.json` (5 MB) — all three carry build-time-only warnings on their loaders, and reading one from a request-time path rebuilds the Fluid Active-CPU shape TASK-M71 had to fix. **The cheap way is usually already there:** the `enrichment` summary rides on every player row (trophies · honours · awards · caps · international goals · career fee), so honours/fees/caps facts cost nothing. Measure the file before wiring it up.
- **⚠️ `<html lang="ar" dir="rtl">` is NOT evidence that a page is localized.** It comes from `params`, not from next-intl, so it stays correct while every translated string is English. Nor is an "is the Arabic data right?" test: entity names resolve through `getEntityNames(locale)` from an **explicit** argument and keep working independently of the message catalog — `tests/e2e/ar-data.spec.ts` asserted an Arabic player name inside a fully English UI and passed. **Count Arabic codepoints, or assert a message-catalog string.** Grepping for a phrase does not work either: next-intl serialises the whole catalog into every page, so the string is always "found".
- **Time-Machine eras** — `src/utils/era.ts#eraForSeason` skins the UI per era via a `data-era` attribute + era-scoped `globals.css` overrides. See `docs/design-system.md`.
- **Motion** — mostly CSS/Tailwind + View Transitions, all `prefers-reduced-motion`-gated. See `docs/motion.md`. `tests/unit/motion-audit.test.ts` enforces the keyframe-property allowlist + reduce gates.

### `features/game/` — the football sim (Phase 18)

A playable game built on the committed data, route-split under `/game/*`. Its layering is stricter than the rest of the app and the rules below are load-bearing — see `TASKS.md` Phase 18 for the tickets.

- **`domain/`** — pure, browser-safe, **no I/O and no entropy**. The match engine, ratings, eligibility, formations, the draft-room deal. `adapter/` — the sole raw-JSON boundary, `import "server-only"`. `view/` — presentation logic (view models, reducers, streams). `components/` — the `.tsx`.
- **⚠️ Never import `adapter/*` from a client component.** Those are `server-only`; client code uses `domain/` + `view/` only.
- **⚠️ Determinism is the core invariant.** A match replays byte-for-byte from `(setup, seed, decisions[])`. Nothing the engine or a deal reads may touch `Math.random()` or `Date.now()` — a seeded `mulberry32` is the only entropy source. Timers and clocks live in components: a countdown **picks** something, and that pick is the input.
- **⚠️ Every `/game/*` route is `force-static`.** `tests/unit/game-routes-static.test.ts` asserts the directive — a route silently going dynamic is what caused the 2026-07 Vercel Active-CPU pause.
- **The routes:** `/game` is the **mode gate**, `/game/demo` the broadcast showcase, `/game/draft` the canonical loop (Tactical H2H), `/game/chaos` the Chaos Draft, `/game/daily` the daily challenge (TASK-1817). `/game/play` was byte-identical to `/game/draft` and is now a `next.config.ts` redirect, not a route. Only `/game` is in `NAV_ITEMS` and the sitemap — the sub-routes are app surfaces, not content. A floating `<DailyBubble>` in the locale layout links to `/game/daily` from every page; it is the one piece of game UI mounted outside `/game/*`, because the header's width budget is already spent.
- **⚠️ The daily challenge is derived entirely from the UTC date, and three of its rules are load-bearing (TASK-1817).** `domain/daily.ts` reads **UTC getters only** — local getters break the "same challenge everywhere" premise invisibly, since the developer's own machine usually agrees. The day key is **anchored at kickoff** and immutable for the session, so a match kicked off at 23:58 and finished at 00:03 records under the day it began; nothing inside a live session may re-read the clock, and resume is current-day only. And `DAILY_SHAPES` is **frozen, not append-only**: the pick is `hash(day) % length`, so appending re-maps every past day exactly as reordering would — a golden table makes any edit fail loudly rather than silently invalidate stored history. Streaks are **derived** from the record list on every read (`domain/daily-stats.ts`), never stored, and the walk steps through `dayKeyOffset` so a gap day breaks a streak instead of being treated as contiguous. ⛔ The `sessionStorage` start marker is a **speed bump, not a lock** — per-tab, dies with the tab, and cleared by the same "clear site data" that wipes IndexedDB. No client-side measure can be authoritative here, which is why there is no global leaderboard; do not build one on it.
- **The mode roster is DATA.** `domain/modes.ts` is the single registry behind the gate: each mode's group, entry route, and status **per format** (`single` / `season`). The gate renders from it and never branches on a mode's identity, so unlocking a mode later is a data change, not a component change. `tests/unit/game-modes.test.ts` guards it — unique ids, every `live` format pointing at a route that exists, every label key resolving in **both** locales.
- **⛔ `n/a` is not a weaker `planned` (owner, 2026-08-24 — TASK-1841).** A mode's format status is `live | planned | n/a`: `planned` is a promise the roadmap intends to keep and renders as TEXT; **`n/a` means the format will never arrive for this mode and is not rendered at all**, because a locked box promising it is a lie rather than a roadmap. The daily forced the distinction — a season-long "one challenge a day" is a contradiction. A playable mode with exactly ONE applicable format (`isDirectEntry`) renders a **link straight in** rather than an expander over a single destination. ⚠️ The gate's guard test counts expanders against the playable modes, so it must count direct-entry tiles by **`href`** — the old form was one short AND would have passed if the daily had lost its control entirely.
- **⚠️ Locked modes render as NON-FOCUSABLE elements, never disabled buttons.** Nine locked tiles as disabled buttons would be nine dead stops in the tab order leading nowhere. Same rule for a `planned` format inside an expanded tile.
- **⭐ `/game` is the ARCADE CABINET (TASK-1833) — and a per-mode ACCENT is the answer to "mostly grey".** Seven of eleven modes are locked; the old gate dimmed them and read as an unfinished game. Each mode now carries its own colour on `GameMode.accent` (beside `emoji` — a mode's identity arrives WITH the mode; a component-side lookup keyed by `ModeId` is a second registry that can drift), a playable one is lit and an unbuilt one is the same sign switched off. Marks are **8×8 pixel grids** (`ModeMark.tsx`), not vector paths — the grid is the arcade's own language, and a monoline mark fights the surface. The format step is a **cursor select**: a ▶ against what you can pick, which states the planned-is-not-a-control rule better than two boxes did. ⚠️ The "Play now" / "Coming soon" split is GONE — two sections made the locked list a wall of its own. ⚠️ Scoped to `.mg-root`, never `:root`, and committed to one dark treatment in both app themes.
- **⛔ A HYBRID of animation concepts can create a bug neither half has (TASK-1833).** The owner's pick was flicker + bloom + neighbour-dim, which compose only because each acts on a different element with a different property (`opacity` on the panel, `box-shadow` on the tile, `opacity` on the siblings). But "dim everything that is not open" animates from `opacity: 1`, and a locked slot already sits at `.4` — so composing them made every unbuilt mode **flash brighter before dimming**. Two rules, each dimming from where its state actually is. ⚠️ And its guard test was **vacuous in its first form**: `css.toContain(selector)` stayed green with the rule deleted, because the same selector also appears in the reduced-motion gate lower in the file. Assert the RULE (`selector {` + `animation:`), not the selector.
- **Every game surface goes through the owner's 30-concept ritual, and the picks are now SHIPPED (TASK-1834/1835/1836).** `/game/draft` is **"The Market"** (stadium ticker, the pool as real `PlayerCard` faces in a Y-only scrolling wall, a vertical pitch whose chips carry each man's OVR, all 20 formations as grouped chips, a full-width pulsing Play). `/game/chaos` is **"Match Night"** (versus board with both averages and shapes, one pitch showing both XIs, the squads facing each other with every card flip-revealed, Play 80% / Re-roll 20%). `/game/daily` is the **"Arcade Cabinet"** (marquee carrying the closing clock above day+streak, the Gazette beneath it, a trophy strip, a pitch that collects each pick, a full-width 28-day heat calendar, and a **full-screen pick overlay** that closes itself on the eleventh pick). Build the gallery PLAYABLE against the real rules — a static mockup gets rejected — and see `docs/` history plus the memory note for the ritual's mechanics.
- **⛔ A face-down card wears the app's OWN back — `CardBack` + `pickBack`, never a hand-written panel (owner, 2026-08-23).** `PitchDraft` dealt its five candidates onto a grey `linear-gradient` for months; the reveal now turns onto the same seeded K01/K02/K07/K09 artwork a tap flip would show. `CardBack` is exported from `PlayerCard` for exactly this. ✅ **The directive is COMPLETE (TASK-1839):** `DraftRoom`'s candidates were the last holdout — small text tiles, so `room-flip-in` started **edge-on at `rotateY(90deg)`** because there was no back face to turn off. They are scaled `PlayerCard`s dealt on real `CardBack`s now, and the keyframe runs the full 180° with no fade. ⛔ **A CSS comment can be aspirational**: that keyframe's comment had said "candidates arrive face-down and turn over" since TASK-1823, and it was untrue for as long as the tiles were text. ⚠️ When an animation moves down a layer, **its reduce gate moves with it** — a gate left on `.room-card` would silence an element that no longer animates while the card kept turning.
- **⛔ A pack is ROUTED the moment it is in `RULE_PACKS` — `routedPacks()` never reads `domain/modes.ts` (TASK-1810).** It filters on `chooser != null` against that list alone, so "the mode is still `planned` in the registry" does NOT keep it off the routes. Registering Captain's Draft before `[mode]/[club]` understood a captain chooser **broke the Vercel build**: the route fanned out `captains × 51 clubs`, handed each CLUB id to the pool builder as a captain id, and the empty pool killed the prerender on `shape.slots`. A pack lands in `RULE_PACKS` only once its routes resolve its chooser kind.
- **⛔ "Not dealt" and "not in the pool" are DIFFERENT QUESTIONS (TASK-1810).** Captain's Draft places its icon rather than dealing him, and the first design excluded him from the pool for that reason — but `replayWith` rebuilds a saved XI by resolving every `cardId` against the pool and returns null on the first miss, so an icon left out makes his own match **unresumable and his share link dead**, presenting as "the link is broken" rather than as a missing card. He is in the pool; `roomDeals`'s `excludePlayers` keeps him out of the hands. ⚠️ It excludes a **PLAYER**, not a card — a man is one card per season, so dropping one `cardId` lets his 2019 card be dealt while his 2020 card wears the armband, and a fixture giving each man ONE card cannot catch it.
- **⛔ A recipe's BREADTH is a payload decision, and it must be measured before it is built (TASK-1810).** Every `/game/*` route is `force-static`, so the whole pool is baked into the page. Captain's Draft's "nationality ∪ era" filter measured at **2,619 distinct players / ~1.28 MB on average**, and 3,889 — **76% of the dataset** — for a nineteen-season English captain, which is not a synergy at all. Bound it: one card per distinct player, ranked, capped, with a **reserve** for the half that would otherwise be drowned (England's 1,767 players lose to a ~3,000-strong era every time). ⚠️ And **memoise a whole-dataset scan**: the data FILES are cached by `loaders.ts` but `loadRatedSquad` recomputes ratings on every call, so 46 pages × ~680 squad computations is ~31,000 — about 18× Legacy's entire build.
- **⛔ A rule that reads the DEALT HANDS is bounded by the hands, not by the pool (TASK-1810 Budget Cap).** Budget Cap prevents a dead-end by reserving the cheapest card of every unfilled HAND, so what bounds the draft is the sum of those minimums. Measured on the real pool: a 4-3-3's **pool floor is €46M**, but five random cards per slot put the **dealt-hand floor at €137M–265M** — far above the €100M cap, so every card in every hand was disabled and the mode was unplayable. `DealOptions.cheapest` guarantees the cheapest eligible card per hand and restores it to €47–50M. ⚠️ **Every unit fixture missed this**, because a hand-crafted pool has a cheap card in every hand by construction; a real browser found it in one click. ⚠️ And note which guarantee is possible: **`cheapest` is STATIC** so it can be decided at deal time, while "something he can still afford" is spend-dependent and cannot — `roomDeals` deals every hand from one seed before a single pick exists.
- **⛔ A cross-era PRICE must be indexed, and the basis is the top 50 — never the median (TASK-1810).** PL market values inflated 6.4× on the median card between 2004 and 2025, so unindexed the only rational strategy is "buy the 2000s". But the middle of the market inflated faster (≈6.5×) than the top (≈4.3×), so a median basis is wrong in the _opposite_ direction: an 88+ player from 2004 costs €179M against €101M for one from 2024. The top-50 basis holds every rating band flat to 1.13–1.37×, with the cheap band drifting up and the elite down, so no era is farmable. ⚠️ The factor table is **frozen** (`domain/market-index.ts`), which is what freezes the _window_: a new season arriving in `data/` has no factor and is simply not drafted, so nobody's share link dies.
- **⛔ A price the PLAYER sees is a GAME currency; the real value is only the ORDERING (TASK-1810).** Shipping indexed market values raw produced a **£104M card against a £100M budget** — unreadable and absurd. Budget Cap now maps each card's percentile in the pool onto an FPL-style band (`FLOOR 4.0m + 15.5m × p^2.0`, integer tenths of a million — `domain/price-band.ts`). ⭐ Compression is safe because **a bargain is a RANK DISAGREEMENT between rating and price**, and any strictly monotonic map preserves every one: Vardy 2015 stays 91-rated at £8.5m beside Rodri 2020, 91-rated at £15.1m. ⛔ Map by PERCENTILE, never linearly — market values are so skewed that a linear rescale crushes ~90% of the pool into a £3 band. ⚠️ Integer tenths, not floats: the reserve sums ten prices per render and compares against the cap, so drift would show as a card that is affordable on one render and not the next.
- **⛔ Compressing a price range compresses the DIFFICULTY with it, and only measuring shows it (TASK-1810).** Squeezing a 40× range into 4.9× made quality nearly free — £100m bought **97% of the best possible XI**, where the same cap had bought 86% before. Deepening the pool does NOT fix it (1,800 cards moved it to 95.2% at triple the payload); the **curve exponent** is the lever. Measure what a budget buys against the ceiling after ANY change to a price scale, and measure the human-facing range too — the optimal solver and a coach drafting from five random cards give very different answers.
- **⛔ A squad that is longer than its formation must be SPLIT in exactly one place (TASK-1810).** Budget Cap drafts sixteen — the XI plus a bench the coach pays for — and `buildSession` slices at `formation.slots.length`. That single seam is why the drafted bench survives storage, the share code and both replay paths without any of them learning that benches exist: they all carry one ordered list of card ids, and an empty tail means "XI only", so every other mode is untouched. ⚠️ The share codec's card block was always `_`-delimited; only two length checks pinned it to eleven. Widening them to a **bounded** 11–16 keeps every code already in the wild decoding identically — bounded because a share code is untrusted input.
- **⛔ An index past the end of a formation is a CRASH, not a fallback (TASK-1810).** `shape.slots[i].role` returns `undefined` for a bench index and throws on `.role`, which took down the entire draft screen the first time a bench slot was opened. A browser found it; type-checking and 126 unit tests did not, because nothing in them opened index 11. Route every role lookup through one helper that falls through to the bench list.
- **⛔ A screen that can be REACHED must be able to be LEFT, and "reconsiderable" has two halves (TASK-1810).** Budget Cap shipped `lockPicks: false` as _re-offer the hand_ and nothing else, which locked the page: with the squad full and £1.2m of change, tapping a filled position dealt a hand where **every card was disabled**, and a `round` veil has no close control, no backdrop dismiss and no Escape. The strings they overwrote had been _correct_ for Legacy. ⭐ **Each sentence is keyed on the pack field that makes it true** — finality on `lockPicks`, the 80+ promise on `standout`. ⚠️ **Do not fold the two together even though it works today**: all three shipped packs have `lockPicks === standout` (Legacy and Captain's true/true, Budget false/absent), so a combined string is ACCIDENTALLY correct now and becomes a lie the day a pack ships `lockPicks: true` with no standout — a legal spec. The control test for exactly that trap is in `budget-draft.test.tsx`, and all three sabotages were verified to fail.
- **⛔ A pre-match screen shows the opponent from the LIVE SESSION, never a fresh draw.** The daily preview takes `driver.match.away` — the eleven `buildSession` derived from the day's match seed. Drafting one on the preview screen would show the coach a side he never plays, and it would look right.
- **⛔ A setup screen that DRAFTS must hand its SEED up with the XI (TASK-1838).** `buildSession` re-runs `chaosMatchup` from the seed to derive the coach's **bench** and the **rival**, so `confirmSquad` drawing a fresh `randomSeed()` re-draws the opponent between the versus board and the kick-off: the coach walks out against eleven men he was never introduced to, and every screen looks correct. It is the same rule as the bullet above, seen from the other end — one says never re-draw at the preview, this says never re-draw at the hand-off. ⚠️ `presetSeed` is **optional and normally empty**: every setup that builds only the coach's own XI keeps fresh entropy per match. ⭐ The guard test reads the away XI off the **board** and off the **programme** and compares the two — asserting against `chaosMatchup(pool, seed)` would re-derive from the same seed and agree with itself no matter what.
- **⚠️ The armband passes down the WHOLE ranking, not just captain → vice (TASK-1838).** `Captaincy` carries an `order` (the full XI ranked by the same real-captaincies-then-rating rule) and `armbandAt` walks it. With only two names, substituting both leaders printed "no recorded captain" with nine men still on the pitch — a sentence about the DATA in a situation purely about who is still playing. ⚠️ The handover line dates the change to the **latest** exit among the men ranked ahead of the current wearer, because "the minute the captain left" is the minute the _vice_ took it. ⚠️ `order` is optional so a two-name literal still works, and it falls back to `[captain, vice]` — which is why a fixture built that way cannot catch a regression here; the test must rank a real squad.
- **⚠️ Pre-match is a PHASE, not a route.** The live session — generator, seed, drafted XI — lives in `GamePlay`'s memory, so navigating to a separate URL would drop it. The URL already mirrors the phase as `?phase=preview`.
- **The header's width budget is measured, not guessed.** Nothing in that row can shrink, so its width is the sum of its parts and every `PRIMARY_NAV_HREFS` entry spends real budget. Since TASK-M79 the pill row appears at `lg` (not `md`) and the ⌘K button is icon-only between `lg` and `xl`, which makes **1024px the tight width**: 88px logo + 454px nav + 258px controls + 32px gaps + 64px padding = 896px of the 1024 available, ~128px spare. A seventh pill (~72px) fits. `/compare` sits in "More ▾" by editorial choice now, not by force. Verify any change with `tests/e2e/header-overflow.spec.ts` (twenty widths × both locales) rather than by arithmetic. Below `sm` there are no pills and the budget is tighter still — TASK-M80 bought it back by collapsing the season chip to its glyph and moving the locale switcher into the drawer, so those two are spent.
- **⚠️ Resolve a formation with `formationByName`, never `FORMATIONS[i]`.** The array's order is presentation only; a guard test fails on index access. Variant names carry the shape ("4-3-3 Holding", not "4-3-3") because `formationKey` is `` `${name}/${slots.length}` `` and every shape is 11 slots — a collision restores a saved match into the wrong shape.
- **⚠️ A share code is UNTRUSTED input, and its formation travels as a NAME SLUG (TASK-1812).** `formationKey` is `` `${name}/${slots.length}` `` — a slash, spaces and capitals, e.g. "4-3-2-1 Christmas Tree/11" — so it can never go in a URL, and an index into `FORMATIONS` is forbidden because that array's order is presentation only. `formationSlug`/`formationBySlug` carry identity instead, guarded by a test that the 20 slugs are unique (a collision restores a match into the wrong shape). The shipped codec validated a regex that **rejected all 20 real formations** and its tests passed only because the fixture used `"4-4-2"`, a key no formation produces — **a fixture that cannot occur proves nothing**. The coach's decisions ride as a **token stream** (`domain/decision-tokens.ts`), one token per decision, materialised against the decision the engine actually raises — so a stale or tampered code is REFUSED rather than replayed into a different, plausible match. Resume and share are **one replay path** (`replayWith`); they differ only in drift policy — resume discards, share keeps its own replay and warns.
- **⛔ `Intl.NumberFormat("ar")` returns WESTERN digits** in the browser — measured, not assumed. Use `localizeDigits` from `src/utils/format.ts` for any number the user sees, including text painted into a canvas. And **abbreviating a name by stripping to `[A-Za-z]` yields an empty string for Arabic**: that is why every Arabic scoreboard read "TBD" on both sides until TASK-1812's verification pass. Non-Latin names render whole.
- **⛔ A coach's answer must be ENCODABLE, and `encodeTokens` throws when it is not (TASK-1810).** `buildShareCode` runs **during `GamePlay`'s render** on the full-time screen, so a throw there takes the whole page down with the app's error boundary — the crash is three components away from whatever produced the answer. Two rules the grammar enforces: a `sub-offer` may **not** carry a `reason`, and a `dismissal` may **not** both substitute and reassign. ⚠️ `defaultAnswer` **attaches a reason** whenever `engineSuggests` is true, so any path that answers with it must strip the reason first — that is exactly what crashed every Legacy match that made an automatic substitution, and `share-link.test.ts` had already written the rule down ("no coach path sets one"). **This bites test drivers too**: a driver standing in for a coach must not use `defaultAnswer` for sub-offers. The token heads are `-` noop (run-length), `s` sub, `o`/`z`/`h` response, `i` injury, `d` dismissal, `g` emergency keeper — `inGoal` is its OWN head rather than a third field on `d`, so a stream trying to do both is _ungrammatical_ rather than merely odd, which is what lets a tampered code be refused instead of replayed into a different, plausible match.
- **⚠️ The keeper: substitutable by the COACH, never by the engine (TASK-1810).** `legalOffFor` includes the goalkeeper — that list is the coach's menu — while `pickPlayerOff` keeps its own outfield-only filter, so the engine still never hooks its own keeper. If a keeper is sent off with **no substitutions left**, the dismissal decision carries `keeperGone` + `emergencyKeepers` and the coach puts an outfielder in goal; the mechanism is simply flipping that player's `role` to `"GK"`, because the engine finds a keeper by role and `powerOf` weights by role. ⛔ **No event is emitted** for it — a `substitution` whose `subOnPlayerId` is its own `playerId` commentates as "X replaces X". ⭐ **Measured before testing**: across 400 seeds the engine dismisses a keeper **39×** and offers an emergency keeper **0×**, because substitutions are always still available; a driver that spends the bench first produces **20** real opportunities. The obvious fixture is vacuous.
- **The bench is a REQUEST, not an instant substitution (`view/coach-policy.ts`, wired TASK-1810).** Pressing Bench when a change is already on offer opens the dialog; otherwise it _asks_, and the dialog opens itself at the next stoppage — or after `REQUEST_GRACE` (5) minutes, because the engine emits no ball-out-of-play event and an unbounded wait reads as a broken button. Opening spends the opportunity. ⛔ The open-at-stoppage effect must be declared **before** the auto-answer effect, and that effect skips while a request is pending: effects run in order, so the offer would otherwise be answered away in the same commit and the dialog would open onto nothing.
- **⚠️ Reduced motion must FOLLOW the clock ceiling, not merely start at it.** `minute` is seeded from the ceiling once and the clock effect returns early when `reduced`, so without an effect tracking the ceiling the view sticks at whatever minute the FIRST decision landed on and never shows the rest of the match. Fixed in both `MatchLive` and `MatchView`; measured at **5 of 10 runs failing** without it.
- **⚠️ `DraftPolicy` is `random | best | strong`.** `strong` is a seeded draw over the cards at `STANDOUT_OVR` or better, falling back to the best available — the quality of `best` with the variety of `random`, which is what a club you can face repeatedly needs (a side that always fields its single strongest XI is the same match forever). ⛔ Its rng is drawn **before** the band is checked, so every slot costs exactly one number whether or not the club has cover there; moving that draw inside the branch makes a MIXED club's XI depend on how many slots happened to find a standout. A fixture that is entirely above or entirely below the bar cannot catch it — the guard test needs a mixed one.
- **⚠️ A mode's OPPONENT is part of its rules, and a draft that guarantees quality needs one (owner, 2026-08-19).** Legacy's hands guarantee an 80+ standout every round, so the coach's XI is top-decile by construction; drawing his opponent uniformly from the SAME club-history pool — hundreds of squad players — made every match a mismatch decided by the draft rules rather than by the pitch, and no amount of re-seeding fixes a distribution problem. Packs declare `opponent?: DraftPolicy` (`"best"` = highest-rated eligible per slot, no entropy at all). ⛔ Declaring it ALSO withholds the coach's XI from both auto-drafts — both sides draw from one pool, so best-available otherwise fields the very men he just picked. ⛔ The policy must reach **every** path that rebuilds the match: resume and share both re-run `buildSession` and verify by fingerprint, so a replay that forgot it drafts a different opponent and presents as a corrupt save. The exclusion is gated on the policy rather than applied unconditionally, so `/game/draft`, `/game/chaos` and every stored daily challenge keep their exact bench.
- **⛔ A VAR-disallowed goal must be removed from the commentary tally at its VERDICT minute, not suppressed at its own (owner, 2026-08-19).** `commentate` incremented on every `goal` event and never decremented, so every scoreline printed after a chalked-off goal was inflated by one — the feed's own full-time line read 1–2 beside a scoreboard reading 0–2. The goal is given first, in full, and only then doubted; that is the drama `disallowedAt` exists for, and it is the same clock rule `view/score.ts#scoreAt` follows. Two counters over one event list will disagree unless both obey it.
- **⛔ A pitch is not text — pin it to LTR (owner, 2026-08-19).** `PitchDraft`'s spots were placed with `inset-inline-start` while its goalmouths (`.pd-box-left`/`.pd-box-right`, the halfway line) and its `translate(-50%,-50%)` centring are PHYSICAL, so under `/ar` only the players mirrored: the keeper stood in the centre circle and the forwards on their own goal line. The pitch carries `dir="ltr"` — the one surface in the app that opts out of RTL. ⚠️ Asserting the inline `insetInlineStart` values cannot catch this; they are identical in both locales, which IS the problem. Assert the container's direction.
- **⛔ Canvas geometry belongs in `domain/`, not in the paint function (owner, 2026-08-19).** The share card's scorer list was three constants inside `SummaryCard`'s paint — start 418, step 28, cap 6 — that nobody ever compared against the footer at `H − 74`: a sixth scorer landed at 558 against 556 and printed straight through it, and the overflow "+N" landed exactly on the URL baseline. **No test could have caught it** — a canvas paints in jsdom's void, which is the whole reason `domain/summary-card.ts` exists. `scorerLayout` now owns the arithmetic and a test asserts the block never reaches `FOOTER_TOP` for any count.
- **⛔ A share link must point at the route the match was PLAYED on (owner, 2026-08-19).** `shareUrl` hard-coded `/game/draft`. A code carries card ids, and a card only resolves against the pool the RECEIVING route ships — Legacy's pools are per-club — so every Legacy "Copy link" produced a URL where `replayShared` returned null and the recipient landed on an ordinary draft hub with no sign anything had failed. The route comes from `usePathname()`; `/game/draft` stays the default for the packs served there.
- **⛔ A decision must be answered EXACTLY ONCE, and the guard belongs in the driver (owner round 2, 2026-08-19).** The live screen answers from an effect, and React double-invokes effects on mount in development — so the first decision was answered twice. The duplicate both landed in `answers` and advanced the stream, answering the NEXT decision with a reply shaped for the previous one; the saved match and the share code carried it, and the replay (which cannot duplicate anything) refused the stream. **It presents as "the copied link does not work"**, pointing at the codec rather than at the driver. ⚠️ "Is anything pending?" is NOT a sufficient guard — by the time the duplicate arrives the stream has advanced, so something always is. `useMatchDriver` compares the answer's `kind`/`minute`/`side` against the decision actually awaited; every legitimate answer is built FROM its decision (`answerFor`, `defaultAnswer`, the bench dialog, the emergency keeper, the token replay), so it can only ever reject a stale one. ⭐ **Found by probing the live page after two test harnesses failed to reproduce it — and one of those passed with the fix removed.** Every other determinism test drives the stream directly, so the driver was never in the round trip; `game-match-reproducible.test.tsx` is.
- **⭐ A rival is a CLUB, and its squad is a prerendered route, not a prop (owner, 2026-08-19).** `/api/game/rivals/[club]` is `force-static` + `dynamicParams = false` + `generateStaticParams`, so Next writes one JSON file per club at build and the CDN serves it — the draft screen fetches only the club that was picked. **Measured:** a club's full history is ~900 cards / ~640 KB, but one card per DISTINCT player (his best season) carrying only what `PlayerCard` and the engine read is **~24–31 KB**; all 51 as a prop would be ~1.2 MB on a page already carrying ~700 KB. ⛔ The selection is **everyone at `STANDOUT_OVR`, plus at least `RIVAL_MIN_PER_ROLE` eligible per role** — the per-role top-up is not a nicety: a club's best-rated players are overwhelmingly outfield (Liverpool's top 40 contains ONE keeper), so a rating-only pool leaves the draft with no goalkeeper and `canPlay`'s last-resort fallback puts a striker in goal. ⛔ The rival club and its policy are part of the match's **IDENTITY** — they ride in `SavedMatch` and in the share code (which is why the codec is `v2`, with **no upgrade path** from v1: "upgrading" one means inventing an opponent the sender never faced), and both the resume and the share path must fetch the club's cards **before** replaying.
- **Client persistence** is `features/game/storage/` (raw IndexedDB, no dependency). An in-progress match is stored as its **replay tuple**, never a snapshot, and verified on load by fingerprinting its events — a stale save is discarded rather than resumed into a different match.
- **Motion:** keyframes live in `globals.css` and the audit allowlists `transform` / `opacity` / `box-shadow` only. `filter` is rejected and animating a layout property fails, which is why bars animate `transform: scaleX`.
- **⚠️ The key-event overlay animation is THREE animations, and two of its details are easy to break (TASK-1809).** The treatment chosen by the design-gallery pass is a hybrid: `game-event-in` springs the card in on `--ease-pop`, `game-event-rise` cascades the four `.game-event-*` children at 40/110/180/250ms, and `game-event-glow` grows an accent glow that **holds**. ⛔ The accent must travel as the `--game-event-accent` **custom property**, not only as an inline `borderColor` — a keyframe cannot read an inline style, so the glow would silently fall back to its default and every event kind would glow identically. ⛔ `game-event-glow` must repeat the card's resting drop shadow in **both** stops, because it holds its end state and would otherwise drop the card's depth the moment it finishes. Guarded by `game-event-animation.test.ts` (the CSS half) **and** `game-event-overlay.test.tsx` (the component half) — the CSS test passes even if the class names are deleted from the component, so both halves are needed.

- **⛔ A bench request must LAPSE when nothing can honour it (owner-reported, 2026-08-20).** `shouldOpenPrompt` is only ever consulted against a `sub-offer`, and the engine raises those **only between `SUB_WINDOW_START` (55') and `SUB_WINDOW_END` (85')** — so a request made after 85', or any request still standing at the whistle, could never be answered by anything. The Bench button is `disabled` while a request stands, so the coach was locked out of his own bench for the rest of the match and the label read "Waiting for a break in play" all the way past full time. `requestLapsed` is the missing half of the rule. ⚠️ Its `hasOffer` guard is load-bearing: the grace bound makes **both** rules fire on the same minute, so without it a request is thrown away on the very tick that was about to honour it. ⚠️ Outside the window the button says "Substitutions closed" — "waiting for a break" was not merely stale out there, it was untrue. ⛔ **The guard test for the race was VACUOUS in its first form** — asserted at exactly `requestedAt + REQUEST_GRACE`, where the lapse rule returns false anyway because its bound is strict, so it stayed green with the guard deleted.
- **⛔ A side that loses its goalkeeper must PUT ONE IN GOAL (owner-reported, 2026-08-21).** `defaultAnswer` answered every `dismissal` with no change at all, so a red-carded keeper was never replaced: the side played out the match with an empty net while the reserve keeper sat on the bench and ordinary substitutions carried on around him. ⭐ **Measured before and after, over 600 seeds: a keeper is sent off in 56 matches; 47 finished with nobody in goal → 3.** The residue is sides with no bench keeper left (the `emergencyKeepers` path, still unanswered in auto mode — a deliberate open question). ⚠️ This does **not** contradict "the engine never hooks its own keeper": that rule is about a **fit** keeper, which `pickPlayerOff` still refuses to touch. ⚠️ It changes engine output for ~9% of matches, so old share codes and saves for those seeds drift.
- **⛔ A BAKED photo URL must stay recoverable (owner-reported, 2026-08-20).** `adapter/photo-kind.ts` fetches the modern CDN at build time with a 4-second timeout and, on **any** failure, used to record the **legacy 250×250 URL** — which now answers 403 for most codes. That branch cannot tell "the image does not exist" from "our own fetch timed out", so one transient build hiccup became a permanently broken image. ⛔ And because `photoKind != null`, `PlayerCard` skipped the runtime candidate chain **exactly where it was needed**. Andrew Robertson's code, CDN and PNG were all fine (75 kB, 220×280, HTTP 200) — only the baked URL was wrong. The failure branch now keeps the modern URL, and a baked URL that errors hands the card back to the reactive chain.
- **⚠️ Wrong-person photos are an UPSTREAM defect; `photo-blocklist.ts` is the plaster.** The pipeline's Wikimedia name-matching assigns the wrong file (Richard Gough renders "R T Gough Oswestry", a Victorian-looking portrait). A blocked URL produces **no candidates**, so every surface falls back to its no-photo state — **absent beats wrong**, the same rule the manager portraits follow. It lives in source, not in `players-*.json`, so a data refresh cannot silently undo it. ⛔ **Count distinct player IDS, never `(id, name)` pairs**, when auditing shared photos: one player carrying two spellings across seasons ("Phil Neville" / "Philip Neville", both `1002864`) is not a clash, and counting spellings inflated the figure from **12 to 78** and would have condemned dozens of correct photos. Current truth: **12 URLs claimed by more than one player id, affecting 25 players**, pinned as a ceiling by `tests/unit/player-photo-blocklist.test.ts`.
- **Club crests + big-moment banners (owner, 2026-08-20).** `ClubCrest` resolves the committed `/logos/<teamId>.png` and renders **nothing** for an unknown id or a failed load — the away id is null whenever the coach faces his own club's pool. The banner derivation lives in `view/overlay-event.ts`, **shared** by `MatchView` and `MatchLive` rather than copied, so the two screens cannot drift about what counts as a big moment. ⛔ `EventOverlay` is `absolute inset-0`, so `.lg-split-pitch` needs `position: relative` or it escapes and covers the whole page. ⚠️ A banner is a **moment, not a state** — it shows only while the clock reads the event's own minute, which is why a test that advances the clock too far fails against a correct implementation.

### Logging & observability

`src/utils/logger.ts` emits structured JSON. `logger.warn`/`logger.error` forward to Sentry in production (`Sentry.captureMessage`); a fetcher's `catch` funnels errors to `warn` + `return null` so the page degrades to its empty-state path. `GET /api/health` returns `{ status, commit, uptime, data: { lastRefresh, datasets } | null, ts }` — wire an uptime monitor at this URL.

## Project-specific gotchas

- **pnpm 11 blocks native postinstall scripts by default.** Native deps are whitelisted in `pnpm-workspace.yaml` under `allowBuilds:`. Add a new native postinstall dep there and run `pnpm rebuild`.
- **No client-secret env vars.** The only server secret is `REVALIDATE_SECRET` (gates `/api/admin/revalidate`). Sentry's `SENTRY_AUTH_TOKEN` (source-map upload) + `NEXT_PUBLIC_SENTRY_DSN` (browser-visible) are unrelated.
- **PL season** runs Aug–May — the current season string is `new Date().getMonth() >= 7 ? year : year - 1`.
- **`title.template` in `app/[locale]/layout.tsx` only wraps _child_ segments** — the dashboard sets its title to the absolute form; nested routes inherit the template with a bare-string title.
- **Satori (next/og) doesn't parse OKLCH or CSS variables**, and rejects the `background` shorthand mixing a gradient + hex. Split into `backgroundColor` + `backgroundImage` with hex equivalents. `repeating-linear-gradient` doesn't render (build dashes from real divs). `export const contentType` is invalid in a Route Handler.
- **`instrumentation.ts` lives at the project root**, not `src/`. If you move it, `rm -rf .next` first.
- **Playwright on WSL Ubuntu needs system libs** (`sudo apt install libnspr4 libnss3 libasound2t64` — note the `t64` suffix on 24.04+). `pnpm test:e2e:install` handles it.
- **`useSearchParams()` in the shell (`Header`/`Footer`) needs `<Suspense>`** or the page bails out of static prerender. The header's `<SeasonSwitcher>` is wrapped this way.
- **Never make `players/[id]` read `?season=` (server `searchParams` OR client `useSearchParams`).** It must stay statically prerendered — reading season on the server de-statics every view and a client `useSearchParams` bails prerender, both of which blow the Vercel Hobby Active-CPU cap (the 2026-07 pause). Season lives in `<PlayerSeasonView>` via `window.location` + `history.pushState`; see the Season model section.
- **nuqs `useQueryStates` defaults to `shallow: true`** (no server refetch). Set `shallow: false` when a URL write must trigger a server re-render (see `useComparisonSelection.ts`).
- **⚠️ A leaderboard category's `key` is a `MetricKey`, which can address a nested field** (`"extended.touches"`) as well as a top-level metric (TASK-M83). ⛔ The `Exclude<keyof ComparisonMetrics, "extended">` in that type is **load-bearing**: `"extended"` is itself a key of `ComparisonMetrics`, so without it `key: "extended"` type-checks and `rankBy` sorts **objects** with `>` — which does not throw, it silently produces a meaningless order. Pinned by a `@ts-expect-error` in `leaderboards-index.test.ts` that is enforced by `pnpm type-check` **only** (vitest does not type-check). `buildBoards` must keep its flat signature — `/api/og/leaderboards` calls it; sections come from `buildGroupedBoards` layered on top, and **empty groups are dropped rather than rendered as a heading over nothing**.
- **Testing recharts in happy-dom needs a `ResponsiveContainer` mock** that injects a fixed width/height, else the chart measures 0×0 and paints nothing. See `tests/unit/comparison-radar.test.tsx`.
- **Visual-regression assertions** live in `tests/e2e/dashboard.spec.ts` + `tests/e2e/redesign-visual.spec.ts` via `tests/e2e/_helpers/visual-assertions.ts`. Tailwind v4 emits `oklch()`; the helper rasterises any computed color → sRGB via a 1×1 canvas. Playwright renders the LIGHT theme.
- **Sentry is disabled in dev by default** (Turbopack incompat before Next 15.4.1) — gated by `src/utils/sentry-enabled.ts`. Exercise it via `pnpm build && pnpm start` or `SENTRY_FORWARD_DEV=1 pnpm dev`. The `import-in-the-middle` warnings on `pnpm dev` are harmless noise.
- **`<PlayerImage>` owns avatar resolution** — always render player avatars via `src/features/players/components/PlayerImage.tsx` (it resolves the photo source + falls back through candidates to an initials monogram on `onError`), never `<Image src={player.photo}>` directly. It also accepts an optional **`photoFallback`** (TASK-M87): an absolute URL appended **after** every candidate `photo` produces, used by managers to carry the crawled Transfermarkt portrait. Only an absolute URL is accepted there — a bare id would re-enter the PL-CDN path that just failed and hide a real gap behind a second 404.
- **⚠️ A manager's photo is `bio?.photo ?? id`, and a NUMERIC id resolves to the PL CDN on its own.** Every manager fetcher (`managers.api.ts`, `manager-profile.api.ts`, `managers-index.api.ts`) falls back to the manager's own id, which `<PlayerImage>` turns into a `resources.premierleague.com` URL — managers share the player photo namespace. **So a manager with no stored photo is usually still rendering one**, and any audit of "who has no photo" that reads only the stored bio fields will report false gaps (Iain Dowie was listed as missing while the app had served his headshot all along, and a redundant override was nearly shipped as a fix). The gap is real only for **legacy `lm-*` ids**, which are non-numeric, cannot reach the CDN, and fall through to the initials monogram. Coverage is **292/293** — only Stuart Gray has none, deliberately: the available image was a watermarked stock preview, and absent beats wrong. **TASK-M87 added a fourth rung below the CDN:** the three manager fetchers now also emit **`photoFallback`** from `manager-enrichment.json`'s `photo` (the crawled Transfermarkt portrait), so the full chain is `override → PL-CDN 110x140 → PL-CDN 250x250 → crawled portrait → initials`. It is deliberately _below_ the CDN, so it changes nothing for a manager whose headshot already loads — it fixed exactly two (Oliver Glasner 44410, Andoni Iraola 50428, whose CDN candidates both 404) and covers every future legacy `lm-*` manager automatically. ⚠️ **`<ImageZoom>` has no failover at all** (single static `src`, plain `<img>`, no `onError`) — **TASK-M90**. It affects all three heroes (manager, player, team), not just managers: each passes `candidates[0]`, so a numeric id whose CDN photo 404s zooms to a broken image even though the thumbnail beside it recovered. **Threading `photoFallback` into `resolvePlayerPhotoSrc` does NOT fix this** (M87 already did it) — the fallback is appended _after_ the CDN candidates, so `candidates[0]` is unchanged; it only helps `lm-*` ids, which otherwise get no zoom at all. The fix is to give the lightbox the candidate list + the `failed`-set pattern `<PlayerImage>` already has.
- **MSW handlers are an empty stub** (`tests/msw/handlers.ts`) — the app makes no outbound fetches _from the server_. Component/fetcher tests mock `@/data/loaders` directly. A new MSW handler is a code-smell (what outbound fetch are we testing?). But MSW only intercepts Node-side: during E2E the **browser** still fetches player/manager photos from `resources.premierleague.com` and `upload.wikimedia.org` for real — dozens per page — and Playwright's default `waitUntil: "load"` blocks on them. The suite is not actually offline.
- **E2E specs must import `test`/`expect` from `tests/e2e/_helpers/test.ts`, never from `@playwright/test` directly.** That module wraps `page.goto`/`page.reload` to wait for the App Router to mount (`window.next.router`). Without it, an interaction dispatched before hydration is **silently swallowed**: React suppresses the browser's default navigation but no router exists to handle it, so no RSC request is ever issued and the URL never changes. It presents as a `toHaveURL` timeout, but no timeout value can fix it — nothing is in flight. This was misread as a "nav flake cloud" and cleared with reruns for months. It hits buttons too, not just links (a pre-hydration `<button>` click has no default action to suppress and is simply dropped). Opt out only via `waitUntil: "commit"` (the boot-loader specs, which need the overlay mid-flight), and then call `waitForAppRouter(page)` yourself before interacting.
- **The E2E job runs `pnpm dev`, so routes compile on demand** — `scripts/warm-e2e-routes.sh` (a workflow step) compiles them all up front. Without it the first test to reach a route pays its compile inside a 12s `expect` timeout (`/game/chaos` alone measured 15.3s, above the timeout on its own), and every compile broadcasts an HMR rebuild to every open page mid-assertion. **Add new routes to that script.**
- **`next dev` renders its own static-route indicator with `role="status"`** — a bare `getByRole("status")` in an E2E spec is a strict-mode violation whenever that indicator happens to be mounted. Always scope by accessible name.
- **Pre-commit hook** (Husky + lint-staged) auto-formats staged files. It's locked to the platform that installed `node_modules` — commit from whichever shell ran the last `pnpm install` (WSL). `.npmrc` sets `verify-deps-before-run=false`.
- **⚠️ Radix's `Select.Value` ignores `className`.** It renders its own span, so styling it directly type-checks, reads correctly in review, and does nothing — TASK-M80 nearly shipped a responsive rule that never applied. Put the classes on a wrapper (and remember that moves the value out of reach of the trigger's `*:data-[slot=select-value]` rules). When a utility class on a third-party primitive is load-bearing, assert it in a test rather than trusting the markup.
- **⭐ To attribute Vercel Fluid Active CPU, use the dashboard — not HTTP headers (2026-08-22).** Hobby exposes **no usage API** (cookie-auth only), so the attribution lives in the usage chart's **Type** / **Runtime** tabs and in **Observability → Functions** (invocations + Active CPU per route). ⛔ **The absence of a middleware response header is NOT evidence that middleware did not run** — reasoning from headers produced a confidently wrong answer here. The real split was **middleware (edge) 63.4% / functions 36.6%**, and middleware runs on every page view by construction of next-intl's `as-needed` prefixing, so its cost tracks **traffic**, not any defect. ⚠️ Deploy count does **not** correlate: Aug 11 had 10 production deploys and a tiny bar; Aug 20 had 2 and the tallest.
- **⭐ A 404 CANNOT BE PRERENDERED, so scanner traffic buys a Node render every time (2026-08-27).** Measured on production: `/wp-login.php` and `/xmlrpc.php` matched `/[locale]`, `/wp-admin` and `/.git/config` matched `/[locale]/[...rest]`, and **every one returned `x-vercel-cache: MISS` on every request** — a public site is probed for these around the clock, and each probe was paying a React render to produce a 404. `src/middleware.ts` now answers them with a bare status at the edge (`src/utils/probe-path.ts`), which is the cheapest thing in the stack given middleware already runs on every page request anyway. ⛔ **A DENYLIST of junk, never an allowlist of real segments** — an allowlist is more complete but hands a bare edge 404 to a human who mistypes `/playerz`, and silently 404s any new section whose author did not update it. ⛔ **In the matcher, list the JUNK extensions positively; never write a negative lookahead over the real ones** — the metadata conventions are open-ended (`.txt`, `.xml`, `.svg`, `.ico`, `.png`, `.webmanifest`, and whatever Next adds next), so a lookahead eventually swallows robots/sitemap/PWA with nothing to notice, while a positive list can only ever fail safe. ⚠️ `.well-known` is REAL (ACME renewal, `apple-app-site-association`) and must never be caught. ⚠️ **A unit test cannot prove this works**: `probe-path.test.ts` covers the predicate, but whether those paths ever REACH middleware is decided by the matcher regexes, and only a running server can answer that — hence the `scanner`/`branded404` probes in `cache-guard.yml`. An **empty body** is the fingerprint of the edge answer; the branded page is ~100 KB.
- **⚠️ Vitest does NOT type-check.** A dangling import or a removed symbol survives a fully green suite — only `pnpm type-check` sees it. Run it before claiming done; a green suite is not evidence the code compiles.
- **⚠️ A green suite is also not evidence that nothing changed.** Tests that assert _relationships_ (same seed reproduces itself, the result is one of the valid set) stay green through a total change in output. Going from 4 to 20 formations changed what every seed drafts and not one determinism test noticed. When a change should be user-visible, verify it by measurement, not by the suite staying green.
- **⚠️ React 19 will not flush state produced by a fake timer outside `act`.** A test that advances `vi.advanceTimersByTimeAsync` without wrapping it silently asserts against the un-updated DOM. Wrap the advance in `act(async () => …)`.
- **⚠️ `pnpm lint` can abort with `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`.** pnpm 11 runs a deps check before every script and, with no TTY, aborts rather than prompting. Prefix with `CI=true`. Lint is the one command that must go through pnpm — `next lint` cannot resolve `eslint-plugin-react-hooks` from a bare node invocation.
