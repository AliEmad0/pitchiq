# TASK-1816 What-If Scenarios Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A live `/game/whatif` mode where the coach takes the trailing side of a real Premier League match at the real minute and score of its biggest deficit, gets a team talk, plays the rest on the shared engine, and is judged against history.

**Architecture:** A frozen scenario list in `domain/` derived from committed events (proved by a test). The engine gains one inert optional `MatchSetup.startState` (begin at minute N with a score, dismissals and subs already used) and raises a team-talk sub-offer + response at that minute. A What-If-only `Modifier` (the boost) is fitted so rescues land near 1 in 4. The page is `force-static`; the match fetches the existing prerendered `/api/game/classic/[season]` and ends on `MatchSummary` + post-match report + a verdict banner. Best verdict per scenario lives in IndexedDB.

**Tech Stack:** Next.js 15, React 19, TypeScript, next-intl, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-20-task-1816-what-if-design.md`

## Global Constraints

- All node/pnpm commands through WSL with nvm 22; commit from WSL.
- `domain/` pure (no I/O, no `Math.random`/`Date.now`); `adapter/` server-only and the only raw-JSON boundary; never import `adapter/*` from a client component.
- Every `/game/*` route `force-static`, `revalidate = false`. No new request-time route.
- **With `startState` absent the engine is byte-identical to today.**
- Rescues only (owner). Team talk at the start whistle (owner). Success target **1 in 4**; ship band **15–35%** per scenario (my call, spec). The boost is ONE What-If-only `Modifier` with ONE fitted constant, passed via `MatchSetup.modifiers`, never in `BASELINE_MODIFIERS`.
- Scenario list FROZEN with a golden test; each entry's `startMinute`, `startScore`, `history` re-derivable from `data/events-<season>.json` + `data/fixtures-<season>.json`.
- Verdict = compare `(result, then goal difference)` from the coach's side: `rewrote | matched | repeated`.
- Strings in `en` and `ar`; numbers through `localizeDigits`; any pitch/timeline `dir="ltr"`.
- Owner rituals: 30-concept layout gallery (Task 1) and 20-design motion gallery (Task 8), standalone HTML in `design/what-if-gallery/`, desktop + mobile frames, era + light/dark toggles.
- Merge only when CI **and** E2E are green. Docs (TASKS ✅ Done in row + header, CLAUDE.md, README) in the same PR.

## Review Focus

1. **A scenario that starts after a real red card** — the trailing side starts a man down and its legal XI excludes the dismissed player. Pinned in Task 3 (engine) and Task 5 (session).
2. **Real substitutions made before the start minute** — they count against the season's limit at the team talk (a 1994 side with its 2 subs used gets no sub-offer). Pinned in Task 3.
3. **A real starting XI name that does not map onto the club-season pool** (spelling, missing player) — falls back to the best legal XI, and the pre-match screen says "Best available". Pinned in Task 5.
4. **The coach's side is AWAY** (3 of the 10 listed rescues: Man United at Spurs and Chelsea, Wimbledon at West Ham) — verdict, headline and team talk all read from the away side. Pinned in Tasks 4 and 5.
5. **Replay/determinism with a team talk answered** — the same `(scenario, seed, decisions)` reproduces byte-for-byte, and the team-talk answer is encodable by the existing decision codec. Pinned in Task 3.

### Task 2: Scenario data — derivation + the frozen list

**Files:** Create `src/features/game/domain/what-if.ts` (types, `SCENARIOS`, `verdictFor`); create `src/features/game/adapter/what-if-derive.ts` (server-only derivation from data files, used by tests and Task 5's builder only); Test `tests/unit/what-if-scenarios.test.ts`.

**Interfaces — Produces:**

- `interface Scenario { id: string; fixtureId: string; season: number; date: string; side: Side; startMinute: number; startScore: { home: number; away: number }; history: { home: number; away: number }; sentOffBefore: { home: number; away: number }; dismissedBefore: { home: string[]; away: string[] }; subsBefore: { home: number; away: number }; realXi: { home: string[]; away: string[] } }` — `realXi`/`dismissedBefore` are player NAMES from `lineups-<season>.json`/events, so no lineups file ships to the client.
- `const SCENARIOS: readonly Scenario[]` (frozen)
- `type Verdict = "rewrote" | "matched" | "repeated"`
- `verdictFor(s: Scenario, final: { home: number; away: number }): Verdict`
- `deriveScenario(fixtureId: string, season: number): Promise<Omit<Scenario, "id"> | null>` in the adapter — trailing side = the side with the largest deficit at any goal; `startMinute` = minute of the goal creating it; `null` if the fixture's events do not sum to its final score.

- [ ] **Step 1: Failing tests:**
  - `"⛔ every frozen scenario re-derives exactly from the archive"` — for each `SCENARIOS` entry, `deriveScenario(fixtureId, season)` equals the entry minus `id`.
  - `"⛔ GOLDEN: the scenario ids and start states never change"` — a literal table of `id → [startMinute, startScore, side]`.
  - `"every scenario is a real comeback: trailing by ≥2 at its start, and the real side drew or won"`.
  - `verdictFor`, coach AWAY: history `3–3` → final `3–4` is `"rewrote"`, `3–3` is `"matched"`, `4–3` is `"repeated"`. History `3–5` (real side won by 2) → final `3–6` is `"rewrote"` (bigger margin), `2–4` is `"matched"` (same result, same GD), `3–4` is `"repeated"` (smaller GD).
  - `deriveScenario` returns `null` for a fixture whose events do not sum to the score (pick one from a pre-2008 season).
- [ ] **Step 2:** Run → FAIL (module missing).
- [ ] **Step 3:** Implement. Start with the spec's ten matches; ids are slugs like `"2001-tot-mun"`. `sentOffBefore`/`subsBefore` count real `Card` (red / second yellow) and `subst` events at minutes `≤ startMinute`.
- [ ] **Step 4:** Run → PASS. Commit `feat(1816): frozen What-If scenarios derived from the archive`.

### Task 3: Engine — inert `startState` + the team talk

**Files:** Modify `src/features/game/domain/match-types.ts` (`MatchSetup.startState`), `src/features/game/domain/simulate.ts` (loop start, initial score/state, team-talk decisions); Test `tests/unit/game-start-state.test.ts`.

**Interfaces — Produces:** `MatchSetup.startState?: { minute: number; score: { home: number; away: number }; sentOff: { home: number; away: number }; subsUsed: { home: number; away: number }; dismissed?: { home: number[]; away: number[] }; teamTalk: Side }`.

- Engine behaviour with it: loop from `minute + 1`; side `score`/`sentOff`/`subsUsed` seeded; `dismissed` player ids removed from the XI before play; at minute `minute + 1` the engine first raises a `response` decision for `teamTalk` (with `concededBy: teamTalk`) and then a `sub-offer` with `halftime: true`, `stoppage: true` and `maxChanges` = remaining legal changes, for BOTH sides (the opponent's is auto-answered as today), before any play that minute. All rng draws that happen before the loop today (`added`, referee, weather) happen unchanged.

- [ ] **Step 1: Failing tests:**
  - `"⛔ absent startState is byte-identical"` — for seeds 1..200 on a fixed setup, `hashEvents(simulate(setup).events)` equals a committed golden array captured from `main` **before** this task's code change (capture it first, in this step).
  - `"starts at the given minute and score"` — no event has `minute <= startState.minute` except none; final score ≥ start score per side.
  - `"the first decision is the team talk: a response, then a halftime sub-offer, at minute+1, for the coach side"` — drive `runMatch` and read the first two yielded decisions.
  - `"a dismissed player never appears in events or legalOff"`; `"subs already used reduce maxChanges"` (1994 rules: 2 used → no sub-offer yielded for that side).
  - `"replays byte-for-byte with a team-talk answer"` — same setup + answers twice → equal results; `encodeTokens` accepts the answers.
- [ ] **Step 2:** Run → FAIL.
- [ ] **Step 3:** Implement in `runMatch`. The golden for inertness must be captured before editing `simulate.ts`.
- [ ] **Step 4:** Run the new test + `game-simulate`, `game-match-reproducible`, `game-commentary`, `share-link` suites → PASS. Commit `feat(1816): engine can start part-way through, with a team talk`.
